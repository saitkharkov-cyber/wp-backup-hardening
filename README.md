# wp-backup-hardening

Набор небольших PHP-инструментов и заметок для резервного копирования, диагностики и базового hardening сайтов на PHP/WordPress.

## Назначение

Репозиторий создан как рабочий набор повторно используемых инструментов:

- проверка доступности `ZipArchive`;
- подсчёт размера сайта и количества файлов;
- создание ZIP-архива файлов сайта;
- чек-лист проверки WordPress после заражения;
- парная схема включения и временного снятия hardening-защиты;
- рекомендации по безопасному использованию временных технических скриптов.

Скрипты резервного копирования и диагностики в каталоге `tools/` подходят не только для WordPress, а в целом для PHP-сайтов на обычном shared/VPS-хостинге. Раздел `hardening/` ориентирован преимущественно на WordPress.

## Hardening: включить защиту / временно снять защиту

Файлы в `tools/hardening/` работают как парная схема:

- `harden_8f4c91d7a2e6.php` — включает подготовленный набор защитных ограничений WordPress;
- `unharden_8f4c91d7a2e6.php` — временно снимает эти ограничения перед обновлением WordPress, темы, плагинов или другими работами, которым требуется запись/изменение файлов.

Рабочий порядок: **временно снять защиту → выполнить необходимые изменения → проверить сайт → снова включить защиту**.

Эти скрипты не предназначены для постоянного хранения в публичной директории сайта. После выполнения их следует удалить с сервера. Перед использованием на другом сайте нужно проверить, что правила hardening совместимы с его конфигурацией, структурой каталогов и `.htaccess`.

## Важно по безопасности

Эти PHP-файлы являются временными административными инструментами. Не оставляйте их в публичной директории сайта после использования.

Рекомендуемый порядок:

1. Загрузить нужный скрипт на сервер.
2. Выполнить его один раз.
3. Скачать полученный результат/архив.
4. Удалить скрипт с сервера.
5. Если создавался ZIP в web-root — удалить и его.

Никогда не добавляйте в репозиторий реальные пароли FTP/SFTP, данные БД, API-ключи, cookie, токены или приватные ключи.

## Ограничения

Статическая проверка файлов и сигнатур снижает риск пропустить очевидное заражение, но не является полной гарантией отсутствия компрометации. Для серьёзных инцидентов дополнительно нужны серверные логи, проверка БД, пользователей, cron-задач, прав доступа, актуальности WordPress/тем/плагинов и контроль соседних сайтов в одном аккаунте.
